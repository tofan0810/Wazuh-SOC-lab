# AGENTS.md — Workspace Guidelines & Operating Instructions

## 🛡️ Core Directives for All AI Agents

### 1. 🔒 Absolute Prohibition of Hardcoded Secrets (Zero Secret Leakage)
* **Never Hardcode Secrets:** Under NO circumstances should passwords, API tokens (Telegram, Jira, VirusTotal, AbuseIPDB), private keys, or authentication credentials be hardcoded in any file (`.py`, `.js`, `.json`, `.xml`, `.sh`, `.ps1`, `.md`).
* **Environment-Driven Configuration:** All credentials must be read dynamically from `.env` using environment variable parsers (e.g. `os.getenv("VARIABLE_NAME", "")` or `dotenv`).
* **Safe Fallbacks:** Any fallback for a sensitive variable MUST be an empty string `""` or `None`. Providing fallback passwords like `"test123123"` is strictly prohibited.
* **Template Sanitization:** In configuration templates (`deployment/ossec.conf`, `.env.example`), use only placeholder tokens (e.g., `YOUR_VIRUSTOTAL_API_KEY`).

---

### 2. 🛡️ SOC Architecture & Operational Integrity
* **Safe Host Isolation:** When applying host isolation rules on Windows endpoints, **NEVER block Port 5985 (WinRM)** and **Port 1514/1515 (Wazuh Agent)**. Management channels must remain open to ensure 1-Click Rollback is always operational.
* **Closed-Loop & Self-Healing:** Every containment action must provide an instant rollback mechanism to restore service within 5 seconds without requiring manual host access.
* **SIEM Rule Tuning:** Use **Hierarchical Child Suppression Rules (`level="0"`)** to suppress alerts generated by authorized SOAR remediation actions (e.g., `socrunner` via WinRM/CMD). Do not use leaky inline `negate="yes"` OR clauses that allow attacker bypass.
* **Single Integration Point:** Maintain exactly ONE `<integration>` block for `custom-n8n` in `ossec.conf`. Do not duplicate integrations or run obsolete direct alert scripts.
* **Internationalization:** All interactive ChatOps Telegram messages, inline buttons, and Jira Cloud ticket summaries/descriptions must be maintained in **100% English**.

---

### 3. 🚫 Git Safety & Response Guidelines
* **Do NOT Output Git Commands Proactively:** Do NOT include `git add`, `git commit`, `git push`, or repository manipulation commands in user responses unless the user explicitly asks for them.
* **Verify Changes:** Always verify changes by running test suites (`test_detection_config.py`, `test_soar_closed_loop.py`) before claiming tasks are complete.
